## 3. THE GATE THAT WOULD HAVE CAUGHT IT — designed, measured, NOT LANDED

`tests_emit/test_emit.py::test_the_committed_tree_is_what_a_fresh_run_emits` compares two
file SETS and every byte of the files in both. **An EXTRA file is in neither comparison.**
That is the hole: 2,051 lines sat in the emitted package and no check on either side of that
compare had them in its population.

The converse assertion, written and run in this worktree before the revert, as four clauses
over the table in §2 — no glob anywhere, and every exception named with its reason:

1. every file is emitted, is the derived public composition of an emitted aggregator, or is
   NAMED in the table — a file that is none of the three is the finding;
2. the table names no file the emission writes and no file that is gone (so it can neither
   bless a path the run owns nor go on describing nothing);
3. every module the emission's own TEXT imports from the package is in the table as
   foundation — derived from that text, so a new hand-written dependency cannot be filed
   under the other kind;
4. **no "another generator's output" entry DECLARES A TYPE** — `ast.walk`, so a class inside
   a `try:` or an `if TYPE_CHECKING:` is not a way through.

Both teeth were demonstrated by restoring the file and re-running:

```
clause 1:  1 file(s) of .../src/adcp/types are neither emitted, nor the public composition
           of an emitted aggregator, nor named in NOT_EMITTED: ['registry.py']

clause 4:  registry.py is another generator's output and DECLARES 155 class(es)
           (['KellerType', 'BrandSource', 'RegistryApiError', ...]) inside the emitted package
```

Clause 4 was probed by temporarily filing `registry.py` in the table as another generator's
output — i.e. the escape hatch of *naming* it does not work either.

**This gate is independent of the move and could land on its own**, with `registry.py`
named in the table as a known exception, if the plan wants the hole closed before the

## 5. THE ONE MEASURED DUPLICATION: `FeedEvent` IS `RegistryEvent`

`core/registry-event.json` states the same seven required properties and emits
`RegistryEvent`, reachable at `adcp.types.core.RegistryEvent`:

```
               the document's class                      the OpenAPI copy
actor          str                                       str
created_at     adcp.types._wire.WireDatetime             str
entity_id      str                                       str
entity_type    EntityType             (enum, 4 members)  str
event_id       str                                       str
event_type     RegistryEventEventType (enum, 20 members) str
payload        dict[str, Any]                            dict[str, Any]
```

The consequence is not cosmetic. On
`{"event_id": "not-a-uuid", "event_type": "nope.invented", ...}`:

* `RegistryEvent` **refuses** (`1 validation error`);
* `FeedEvent` **accepts**.

`src/adcp/property_registry.py` and `src/adcp/registry_sync.py` validate the change feed
against the copy that accepts an invented `event_type`.

**And the copy is not even the OpenAPI spec's.** It is literal Python appended by
`fix_spec_reality_gaps` in `scripts/generate_registry_types.py`, under the comment "the
registry feed endpoint now declares its response inline, so datamodel-code-generator no
longer emits the named models" — so a hand-written patch inside a generator duplicates, more
weakly, a type the emission already produces from a document. Repointing those two imports
is a behaviour change (it changes which class a wire path validates against) and needs its
own before/after.

## 6. THE GENERATOR NO LONGER REPRODUCES ITS OWN FILE

Independent of the move, and it matters for any plan that says "regenerate". Running
`scripts/generate_registry_types.py` into a scratch path against the installed
`datamodel-code-generator` produces **2,099 lines against the committed 2,051, differing at
56 lines**:

* seven classes gain `model_config = ConfigDict(extra="allow")` plus a
  `__pydantic_extra__` annotation — a generator-version difference;
* **`CLASS_RENAMES["Pas"]` is DEAD**: the generator now names that class `PassItem`, so a
  regeneration silently renames the committed public name `PolicyExemplarPass` to
  `PassItem`.

`pyproject.toml` already says this file "is carried at upstream's bytes". So a regeneration
today is not a no-op and would ship a renamed public class. **`make regenerate-registry`
also crashes** on this box before finishing: `format_output` invokes a bare `"ruff"`, which
is not on `PATH` (ruff lives in `.venv`), and `check=False` does not cover a missing
executable — so it raises `FileNotFoundError` AFTER writing its output. One-line fix when
the lane reopens: `[sys.executable, "-m", "ruff", ...]`, the way `run_codegen` already
reaches `datamodel_code_generator`.

after the move **no sentence in `src/` may name `adcp.types.registry`** — including the
sentences explaining the move. Four files tripped this. The workable form is to name the
FILE (`src/adcp/types/registry.py`), which the regex does not match.
